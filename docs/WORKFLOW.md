# WORKFLOW — بروتوكول العمل

> وكيل واحد في المرة. ملف تسليم لكل خطوة. بوابة قبل الانتقال.

## السلسلة

```
Planner → Builder → Tester → Reviewer → Curator
   ⛔        ⛔         ⛔         ⛔
```

| الدور | ياخد | يسلّم | ممنوع |
|---|---|---|---|
| **Planner** | المشكلة | خطة + معيار قبول | يكتب كود |
| **Builder** | الخطة فقط | كود + ملاحظات | يغيّر النطاق |
| **Tester** | الكود | اختبارات + نتيجة | يصلّح الكود |
| **Reviewer** | الكود + الاختبارات | موافقة/رفض + أسباب | يعدّل |
| **Curator** | كل ما سبق | درس واحد | يشرح |

## التسليم

```
docs/handoff/<task-id>/
├── 01-plan.md
├── 02-build.md
├── 03-tests.md
├── 04-review.md
└── 05-lesson.md
```

**كل وكيل يقرأ ملف اللي قبله فقط.**

## البوابات

| من → إلى | شرط |
|---|---|
| Planner → Builder | معيار قبول قابل للقياس |
| Builder → Tester | يبني + `verify.sh` بلا أخطاء |
| Tester → Reviewer | اختبار جديد + 630 القديمة خضراء |
| Reviewer → Curator | صفر مخالفة في `INVARIANTS.md` |
| Curator → التالي | درس مسجّل |

## الحدود

| البند | الحد |
|---|---|
| محاولات Builder | 2 |
| محاولات Tester | 2 |
| دورات Review | 2 |
| تجاوز أي حد | **توقف + قرار بشري** |

## قواعد صارمة

1. **مهمة واحدة لكل موجة.** لو فيها "و" فهي موجتين.
2. **Reviewer بموديل مختلف** عن Builder.
3. **لا يعدّل Builder اختبارًا** لينجح.
4. **أي فشل متكرر يرجع للـ Planner** — لا للـ Builder.
5. **كل تغيير يمس invariant** يحتاج سطرًا في `DECISIONS.md` أولًا.
