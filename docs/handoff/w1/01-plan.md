# W1 · Plan — حلقة Tool Calling

**التاريخ:** 2026-10-19
**الدور:** Planner

## المشكلة

التروس الستة عشر موجودة ومحكومة بالكامل (عقد، تحقق، رفض، ميزانية)، لكن **الموديل لا يعرف بوجودها**. كل استدعاء اليوم مكتوب يدويًا داخل عامل. النتيجة: النظام يبدو "وكيلًا" لكنه سكربتات.

## معيار القبول

1. الموديل يستلم قائمة الأدوات، يستدعي واحدًا، يستلم النتيجة، ويكمل في دورة ثانية — كاملة offline.
2. ترس واحد على الأقل يُنفَّذ عبر نفس الجسر المحكوم (`bridge.invoke`).
3. **630 اختبارًا القديمة تبقى خضراء** (ثم 699 بعد الإضافة).
4. لا شبكة ولا اعتماد في الاختبارات.

## التصميم

```
tool_bridge.py   العقد → تعريف أداة JSON-schema
                 + الأسماء الآمنة + المنفّذ
tool_loop.py     الحلقة المحدودة (دورات/استدعاءات)
gateway.py       + complete_turn() : رد قد يحمل tool_calls
worker.py        + run_tools()    : المدخل من العامل
```

## الحالات الأربع

| الحالة | السلوك |
|---|---|
| جواب بلا أدوات | الحلقة تنتهي في دورة واحدة |
| استدعاء صحيح | يُنفَّذ عبر الجسر، نتيجته تُلحق، الموديل يُسأل ثانيًا |
| استدعاء مرفوض | خطأ JSON يُعاد للموديل كبيانات، لا استثناء |
| تجاوز الحد | توقف بـ `max_steps` / `max_tool_calls` — لا استمرار |

## ما لن نفعله

- لا `async` — كل شيء متزامن كما هو.
- لا مكتبات جديدة — stdlib فقط.
- لا تعديل على عقد أي ترس.
- لا أدوات جديدة — فقط كشف الموجود.

## المخاطر

| الخطر | التخفيف |
|---|---|
| الموديل يخترع أسماء | رفض + عدّ + إعادة الخطأ |
| حلقة لا تنتهي | حدّان صريحان |
| تكلفة غير متوقعة | كل استدعاء يمر بـ `spend_control` قبل Socket |
| كسر 630 اختبارًا | لا تغيير سلوك `complete()` — فقط توسعة |
